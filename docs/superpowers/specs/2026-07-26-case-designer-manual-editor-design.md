# 《细胞远征》病例设计器与手动创作流程设计

**日期：** 2026-07-26

**状态：** 设计已在对话中确认，等待书面规格复核

**适用范围：** `/editor.html`、Vue 编辑器入口、病例数据模型、AI病例草案、手动病例创作、试玩、保存与分享

## 1. 背景与结论

当前地图编辑器仍以字符瓦片和旧平台闯关对象为中心。创作者需要理解 `P`、`F`、`p`、`o` 等字符含义，并逐格绘制地形；金币、问号方块、管道刷怪和终点门仍占据主要入口。这种工作流会继续诱导创作者制作“细胞版马里奥”，也无法自然表达供氧、感染控制、患者指标和AI病例危机。

新的编辑器定位不是“地图字符编辑器增加几个病例瓦片”，而是“病例设计器”：

```text
定义患者问题
→ 选择主控细胞与病例模板
→ 布置病例节点和行动空间
→ 配置患者指标、目标与AI危机
→ 实时检查职责闭环和可达性
→ 按目标角色试玩
→ 保存草稿、发布或分享
```

手动创建与AI生成必须使用同一个 `CaseDraft`、同一套领域工具、同一套校验器和同一个发布流程。AI只是创建草案或提出受限修改，不能拥有绕过人工编辑器的第二条通道。

## 2. 目标

1. 不需要理解字符代码，也能在十分钟内做出第一张可玩的病例。
2. 手动创作从“摆放平台元素”转为“设计红细胞供氧或白细胞清感染的职责闭环”。
3. AI生成、模板创建、空白创建和旧地图导入最终都转换为相同病例草稿。
4. 编辑过程中持续说明缺少什么、为什么不能发布以及如何修复。
5. 保留地形绘制自由度，同时让病例节点、目标和患者指标具有语义化属性。
6. 支持红细胞、白细胞和双人协作三种试玩检查。
7. 旧地图和旧分享码可继续导入，不强制破坏历史内容。

## 3. 非目标

- 不制作任意脚本编辑器或可执行事件语言。
- 不让用户自由编写AI提示词并直接改变运行时代码。
- 不在首版提供复杂节点图、行为树或关卡脚本IDE。
- 不要求地图必须由AI生成。
- 不把血小板重新加入角色入口或新病例工具。
- 不把经典模式对象混入新病例的默认工具库。

## 4. 两种内容模式

### 4.1 病例模式

新建内容默认进入病例模式。病例模式只暴露与新核心玩法有关的对象：

- 地形、平台、出生点和存档点。
- 肺泡供氧点、目标组织、感染灶。
- ATP补给、病例危险、知识卡和视觉装饰。
- 患者指标、阶段目标、允许的AI危机和病例叙事。

病例完成由 `CaseEngine` 判断，地图右端和旧终点对象没有通关作用。

### 4.2 经典模式

经典模式用于打开和维护旧地图，保留金币、问号方块、管道、终点门和历史对象。它必须显示“经典玩法，与新病例评分方向不同”的标签。

新建按钮不直接创建经典地图。用户需要从“兼容工具”中明确选择经典模式，避免旧元素继续成为默认设计语言。

### 4.3 模式转换

经典地图可执行“转换为病例草稿”，但转换只完成安全的机械步骤：

- 复制地形和出生点。
- 将旧终点移除并提示添加病例目标。
- 将金币、问号方块和管道列入待处理清单。
- 不自动猜测供氧点、感染灶或患者指标。

转换始终产生新草稿，不覆盖原地图。

## 5. 手动创作主流程

### 5.1 新建向导

“新建病例”分为四步，每一步都可以返回修改：

1. **病例主题：** 标题、器官场景、教育主题和预计时长。
2. **玩家职责：** 红细胞、白细胞或双人协作；单人时自动配置另一类细胞的友军职责。
3. **起点：** 安全模板、已有病例副本或空白病例。推荐安全模板，空白病例标为高级选项。
4. **初始病情：** 标准、轻松、挑战三个预设；随后可在患者面板精调。

完成向导后立即得到可保存的本地草稿。即使地图尚未通过发布校验，也不会因为关闭页面丢失。

### 5.2 工作区结构

病例设计器使用稳定的四区布局：

- **顶部操作栏：** 返回病例库、草稿名称、撤销、重做、保存草稿、校验、试玩、发布。
- **左侧工具库：** 地形、病例节点、危险与资源、知识与装饰。
- **中央画布：** 地图、网格、节点连线、角色可达范围和问题高亮。
- **右侧检查器：** 当前对象属性、病例设置、患者指标、目标和AI危机。
- **底部状态栏：** 错误、警告、地图完成度、鼠标坐标、缩放和当前角色预览。

常用操作保持可发现：每个图标同时有中文名称和快捷键提示，不依赖字符代码。

### 5.3 分阶段引导

编辑器顶部显示五个创作阶段，但不强制锁死顺序：

1. 空间布局。
2. 病例节点。
3. 患者与目标。
4. AI危机与知识。
5. 校验与试玩。

每个阶段显示完成状态。例如红细胞病例在同时存在供氧点、目标组织和有效交付目标后，“病例节点”阶段才完成。

## 6. 手动编辑工具

### 6.1 地形工具

- 单格画笔与橡皮擦。
- 直线、矩形、填充和框选。
- 选区移动、复制、粘贴、翻转和删除。
- 安全片段库：平地、缓坡、跨越区、供氧房、感染区、恢复区。
- 网格吸附、缩放和小地图导航。

连续拖动画笔算作一次历史操作。撤销和重做至少保留50步；切换地图、导入和AI补丁也必须形成可撤销事务。

### 6.2 病例节点工具

创作者放置的是具名对象，不是裸字符：

- **供氧点：** ID、显示名、容量、恢复速度和视觉主题。
- **目标组织：** ID、显示名、所需氧量、组织损耗速度。
- **感染灶：** ID、病原体类型、强度、扩散速率和是否为阶段目标。
- **出生点：** 单人出生或双人红白出生锚点。
- **存档点：** 复活位置和患者状态惩罚预览。
- **知识节点：** 标题、正文、来源ID和准备加成。

底层仍可编译为地图标记，但UI、历史记录和校验都操作语义对象。

### 6.3 节点配对和目标生成

选择供氧点后可以点击一个或多个目标组织建立配送关系。画布显示方向线和预估路线长度。选择感染灶可以加入当前阶段或设置为可选目标。

编辑器根据节点建议目标：

- 一个供氧点连接两个目标组织时，建议两次或三次交付。
- 三个感染灶中选择两个作为必需目标时，清除目标自动设为二。
- 调整目标数不会删除节点；删除目标节点时必须提示受影响的目标和AI事件。

创作者可以接受建议后微调，但不能设置超过实际可完成数量的目标。

### 6.4 患者与阶段面板

面板直接显示对游戏结果的影响：

- 初始血氧、感染、组织活性。
- 每种操作的改善量和自然恶化速率。
- 供氧次数、感染清除数和稳定倒计时。
- 第一阶段和第二阶段的目标摘要。
- 单人自动友军承担的职责。
- 允许AI选择的危机、严重度范围和合法目标节点。

修改数值后，面板即时显示预计难度和无法完成风险，不要求创作者理解内部JSON。

## 7. 统一草稿模型

编辑器内部使用版本化 `CaseDraft`：

```ts
interface CaseDraft {
  version: 1
  mode: 'case' | 'classic'
  id: string
  revision: number
  metadata: CaseMetadata
  map: string[]
  nodes: CaseNode[]
  caseConfig: CaseConfig | null
  knowledgeCards: KnowledgeCard[]
  editorMeta: {
    source: 'manual' | 'template' | 'ai' | 'import'
    templateId?: string
    seed?: number
    updatedAt: string
  }
}
```

约束：

- `map` 只保存地形和必要运行时标记；节点属性存放在具名数组中。
- 节点ID在移动、撤销、复制和AI修改后保持稳定；复制时生成新ID。
- `editorMeta` 用于编辑器提示和证据，不包含提示词、API Key或完整模型响应。
- 发布包只包含运行时需要的白名单字段；编辑历史和本地诊断不进入分享码。
- 所有入口先迁移为 `CaseDraft`，再调用相同校验和保存流程。

## 8. AI与手动编辑的统一

### 8.1 四种入口，一个工作区

以下入口没有独立编辑器：

- 手动空白创建。
- 从安全模板创建。
- AI生成病例蓝图并编译。
- 导入 `CQ2!` 或旧地图转换。

它们都生成 `CaseDraft` 并打开同一个工作区。工具、校验、试玩和发布完全一致。

### 8.2 AI来源的可见性

AI草稿显示来源徽标、蓝图摘要、编译模板、种子、回退原因和校验状态。用户第一次编辑后仍保留来源，但不把病例宣传为“完全由AI保证可玩”。

### 8.3 受限助手

助手只能提出领域操作，例如增加供氧节点、减少感染目标、调整难度或改写说明。处理流程为：

```text
用户选择建议
→ 服务端返回白名单 CasePatch
→ 在草稿副本上应用
→ 完整校验和可达性检查
→ 显示人类可读差异
→ 用户确认
→ 作为一个可撤销事务写入历史
```

助手不得接收自由脚本、任意JSON路径、最终地图文本或存储操作。

## 9. 校验、诊断与修复

### 9.1 三层检查

1. **结构检查：** schema版本、字段、范围、地图尺寸、唯一ID和唯一出生点。
2. **职责检查：** 红细胞目标具有供氧闭环；白细胞目标具有感染灶；双人模式同时具备两类职责；单人自动友军有合法路线或保底配置。
3. **几何检查：** 出生点到必需节点和完成区域可达，跳跃间距、台阶高度、落点和复活点满足实际移动边界。

AI危机还要检查事件引用的节点真实存在，并且至少保留一条当前角色或自动友军能够处理的合法事件路径。

### 9.2 错误与警告

**错误**会阻止发布、导出和排行榜资格，例如：

- 缺少出生点或存在多个同类出生点。
- 目标数量超过可用节点。
- 必需节点不可达。
- AI事件引用未知节点。
- 患者状态在理论最短路径内必然归零。

**警告**允许试玩和发布，但需要明确确认，例如：

- 地图预计过长。
- ATP补给可能不足。
- 存档点距离过远。
- 教育主题缺少来源。
- 标准难度下预计失败率较高。

### 9.3 可操作诊断

问题面板不能只显示“地图非法”，必须包含：

- 问题类型和影响。
- 涉及的节点或数值。
- “定位到地图”动作。
- 至少一个确定性修复建议。
- 可安全自动修复时提供预览和撤销。

保存本地草稿不受校验错误阻止，避免丢失工作；试玩可在结构安全时进行；发布、导出分享码和提交每日挑战必须通过全部错误级检查。

## 10. 试玩闭环

### 10.1 试玩入口

病例设计器提供：

- 以红细胞试玩。
- 以白细胞试玩。
- 双人协作试玩。
- 从当前选中位置快速试玩，仅用于局部移动检查，不计完整通关。

不适用于当前病例的角色入口置灰并解释原因。完整试玩使用和正式游戏相同的 `CaseEngine`、物理参数和AI事件校验器，不能建立编辑器专用的简化规则。

### 10.2 返回编辑器

退出或完成试玩后恢复原草稿和视口，并生成诊断摘要：

- 是否完成病例以及耗时。
- 死亡、复活和患者失败原因。
- 未访问的必需节点。
- 氧气交付路线和感染处理时间。
- AI/本地危机及其目标节点。
- 玩家卡住或反复死亡的区域热区。

试玩数据只用于当前草稿诊断，默认不上传。

## 11. 保存、发布与分享

### 11.1 三种状态

- **自动草稿：** 每次事务后防抖保存到当前存档槽；允许不完整。
- **命名草稿：** 用户主动保存的版本，可复制和恢复。
- **已发布病例：** 通过校验并至少完成一次适用角色的完整试玩，可生成 `CQ2!` 分享码。

再次编辑已发布病例会创建新修订，不静默覆盖旧分享内容。

### 11.2 发布检查单

发布前显示：

- 主控细胞和自动友军职责。
- 病例目标、初始指标和预计时长。
- 必需节点与可达性结果。
- 最近一次完整试玩结果。
- AI危机白名单和离线回退结果。
- 标题、作者、标签、知识来源和封面。

### 11.3 导入安全

只接受版本化JSON或分享码。拒绝JavaScript对象文本、HTML、函数、未知字段和超出大小限制的数据。导入先进入隔离预览，显示模式、尺寸、节点、目标和风险，用户确认后才写入草稿库。

## 12. 技术边界

病例设计器UI以 Vue 3 和 TypeScript 实现，继续保留 `/editor.html` URL。领域能力拆成与UI无关的纯模块：

```text
src/editor/
├── EditorApp.vue
├── components/
├── stores/case-editor.ts
├── domain/case-draft.ts
├── domain/case-commands.ts
├── domain/case-history.ts
├── domain/case-schema.ts
├── domain/case-reachability.ts
├── domain/case-publisher.ts
├── adapters/legacy-level-import.ts
└── adapters/legacy-storage.ts
```

边界要求：

- Vue组件只派发命令和展示不可变快照，不直接改地图数组。
- 所有编辑动作表示为可测试命令，并产生一条历史事务。
- `case-schema`、编译器、游戏加载器和服务端工具使用同一字段定义。
- 迁移期间可提供旧页面适配器，但不得同时维护两套校验规则。
- 物理和病例状态仍由游戏引擎负责，编辑器只调用稳定试玩接口。
- 任何本地存储都通过版本化 repository 适配器，不能在组件中直接拼接键名。

## 13. 兼容与迁移

1. 旧 `CQ!` 分享码导入为只读预览，然后转换为经典草稿。
2. 旧 localStorage 自定义关卡按当前存档槽进行幂等迁移。
3. 旧关卡文件通过安全解析器导入，禁止 `eval`。
4. 经典地图保存时保持旧运行规则；转换为病例后生成新ID。
5. 六个官方病例也通过同一 `CaseDraft` 和发布校验构建，证明编辑器不是仅供UGC使用的旁路工具。
6. 现有地图文件和用户草稿在迁移前生成备份，不进行原地批量覆盖。

## 14. 测试策略

### 14.1 领域单元测试

- 所有命令的执行、撤销和重做。
- 节点复制后ID唯一，移动后引用稳定。
- 目标建议、节点删除影响和自动修复。
- schema、职责闭环和可达性判断。
- 经典导入、CQ2往返和未知字段拒绝。
- 同一蓝图与种子生成同一草稿。

### 14.2 组件测试

- 新建向导四步流程。
- 工具分组和模式隔离。
- 检查器编辑与画布选择同步。
- 错误定位、修复预览和确认。
- 草稿自动保存、版本恢复和离开保护。

### 14.3 浏览器集成测试

- 完全手动创建一个红细胞供氧病例并通关。
- 完全手动创建一个白细胞感染病例并通关。
- 创建双人病例并以红白角色启动试玩。
- AI草稿进入相同编辑器，人工修改后发布。
- 无网络时本地模板草稿仍可编辑、试玩和分享。
- 旧地图导入经典模式且不出现脚本执行。
- 发布失败能定位到具体不可达节点。

### 14.4 人工可用性测试

邀请至少5名未接触字符地图格式的体验者完成：

1. 从模板建立病例。
2. 增加一个目标组织或感染灶。
3. 修改患者初始状态。
4. 找到错误并修复。
5. 试玩并发布分享码。

至少4人应在不查看代码说明的情况下于10分钟内完成；所有人都能说明自己设计的是供氧、免疫或协作病例，而不是“跑到终点”。

## 15. 验收标准

满足以下全部条件才算病例设计器完成：

1. 新建默认进入病例模式，默认工具中没有金币、问号方块、管道和终点门。
2. 创作者不输入任何字符代码即可完成红细胞或白细胞病例。
3. 手动、模板、AI和导入入口都生成统一 `CaseDraft`。
4. 每个病例节点具有稳定ID和可编辑属性。
5. 撤销/重做覆盖地形、节点、配置、导入和AI补丁。
6. 错误可定位、可解释，并提供确定性修复建议。
7. 本地草稿即使不合法也不会丢失；不合法内容不能发布或分享。
8. 红细胞、白细胞和双人试玩使用正式游戏规则。
9. 试玩返回诊断摘要并恢复原编辑状态。
10. 发布病例通过共享schema、职责闭环、可达性和安全检查。
11. AI断网时不影响手动创建、试玩、保存和分享。
12. 旧地图和旧分享码能够安全导入经典模式。
13. 六个官方病例能够通过该设计器的数据与发布流程表示。
14. 自动化测试覆盖手动端到端病例创建和AI草稿人工修改。

## 16. 对现有计划的修订

本规格细化并在冲突处替代既有核心玩法计划中的“Task 7: Case editor schema, validation and round trip”，但不改变 `CaseEngine`、固定单人角色、双人红白协作和AI病情导演设计。

需要在后续实施计划中修订的关键点：

- 从直接修改单体 `editor.html` 改为 Vue/TypeScript 病例设计器组件与领域模块。
- 从“增加三种瓦片”改为语义节点、检查器和目标关系。
- 从“校验失败不能保存”改为“允许安全保存草稿，但阻止发布和分享”。
- 从单次快照重置改为完整命令历史、撤销和重做。
- 增加手动创建端到端测试、角色试玩、诊断回传和可用性验收。
- AI生成任务必须依赖统一 `CaseDraft`，不得继续维护原始字符地图生成入口。

推荐实施顺序为：统一草稿与命令模型 → 基础工作区和手动工具 → 病例节点与配置 → 校验诊断 → 试玩闭环 → 保存发布 → AI接入 → 经典兼容与六关迁移。
