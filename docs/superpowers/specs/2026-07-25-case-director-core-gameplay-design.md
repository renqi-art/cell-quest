# 《细胞远征》病例导演核心玩法设计

> 日期：2026-07-25  
> 状态：已确认  
> 实施窗口：3 天

## 1. 背景

当前版本已经具备横版移动、战斗、ATP、红细胞/白细胞/血小板、六个内置关卡、双人模式、地图编辑器、存档和基础自适应难度。

现有核心体验仍以平台跳跃、金币、问号方块、管道刷怪和抵达终点为主，容易被体验者理解为“细胞版马里奥”。现有 AI 主要用于生成关卡、NPC 对话和规则式难度调整，尚未明确参与核心游戏循环。

本次改造保留横版操作和现有地图系统，将核心目标重构为：

```text
观察患者病情
→ 应对 AI 生成的病例危机
→ 完成供氧或感染控制任务
→ 稳定患者生命指标
→ 获得病例报告
```

## 2. 目标

1. 让游戏胜负由患者状态决定，而不是由抵达地图右侧决定。
2. 让红细胞和白细胞拥有不可互换的生理职责。
3. 单人模式每关固定一个主控细胞，避免关内切换造成额外学习成本。
4. 双人模式固定一名红细胞和一名白细胞，形成真实分工。
5. 通过通用病例引擎和地图编辑器配置重构全部六关，而不是为六关编写六套逻辑。
6. 让 AI 决定每局发生的病例危机、目标位置和阶段顺序，使 AI 成为核心玩法的一部分。
7. AI 断网、超时或输出非法内容时，游戏仍可通过本地导演完整运行。
8. 保留旧存档和旧自定义地图的兼容性。

## 3. 非目标

本轮不实现：

- 关内红细胞/白细胞切换。
- 血小板新玩法、血小板目标或血小板入口。
- 分屏双人模式。
- 复杂友军寻路。
- 可视化规则节点编辑器。
- 超出白名单的 AI 自由事件生成。
- 账号、云存档或在线匹配。
- 新增普通关卡、装备或技能树内容。

## 4. 已确认的产品决策

### 4.1 血小板

- 保留血小板相关类、技能、素材和存档字段，避免兼容性破坏。
- 从角色选择、角色图鉴入口、可见技能树和地图编辑器病例选项中隐藏。
- Q 键不再切换细胞。
- 新病例模式不创建血小板玩家或血小板任务。

### 4.2 单人模式

- 每张地图通过 `caseConfig.primaryCell` 固定主控细胞。
- 玩家进入关卡后不再选择或切换细胞。
- 另一类细胞通过可视化的自动协作系统参与病例。
- 自动协作不执行复杂地形寻路，只运行脚本化支援。

### 4.3 双人模式

- 双人固定为一名红细胞和一名白细胞。
- P1 选择角色后，P2 自动获得另一个角色。
- 选角界面提供“交换角色”，不允许选择相同细胞。
- 单人自动友军在双人模式中停用，由第二名玩家接管职责。
- 共享患者指标与 ATP，各自保留生命值和角色技能。
- 保留现有中点跟随和动态缩放相机，不开发分屏。
- 两人距离超过同屏安全范围时，以柔性边界限制领先玩家并提示“等待队友”。

## 5. 核心玩法循环

### 5.1 单关流程

```text
病例卡
→ AI 病情导演选择第一阶段危机
→ 玩家完成对应目标
→ AI 根据表现选择第二阶段危机
→ 玩家稳定氧供、感染负荷和组织活性
→ 稳定倒计时 5 秒
→ 免疫协作报告
```

每关最多包含两个 AI 阶段，避免网络等待和系统复杂度失控。

### 5.2 红细胞职责

1. 在肺泡供氧点装载氧气。
2. 将氧气运送到目标组织。
3. 每次成功交付提高氧供和组织活性，并恢复少量共享 ATP。
4. 红细胞携带的氧气在本细胞死亡时丢失。
5. 单人模式不会因暂时离开供氧路线而失去已装载氧气。

### 5.3 白细胞职责

1. 定位并清除感染灶。
2. 清除感染灶降低感染负荷。
3. 普通攻击和技能消耗共享 ATP。
4. 感染负荷越高，氧供衰减和组织损伤越快。

### 5.4 单人自动协作

红细胞关卡：

- 自动白细胞以感染区支援的形式运行。
- 玩家供氧越稳定，自动白细胞清除效率越高。
- 自动白细胞使用固定感染点动画，不执行平台寻路。

白细胞关卡：

- 自动红细胞以可视化运输流形式运行。
- 玩家清除运输路线上的感染灶后，红细胞运输动画通过并提高氧供。
- 自动红细胞沿编辑器定义的供氧点和目标组织之间播放，不参与平台碰撞。

## 6. 病例引擎

### 6.1 职责

新增独立 `CaseEngine`，只负责：

- 患者指标。
- 病例目标进度。
- AI 事件的安全执行。
- 稳定倒计时。
- 病例失败和完成。
- 病例统计与报告数据。

玩家、敌人、供氧点和 UI 不直接修改病例状态，只通过事件调用病例引擎。

### 6.2 患者指标

三个指标统一使用 `0–100` 的游戏化数值，不表示临床诊断值：

- `oxygen`：氧供。
- `infection`：感染负荷，数值越低越好。
- `tissue`：组织活性。

基础关系：

- 感染负荷越高，氧供衰减越快。
- 氧供低于安全线时，组织活性持续下降。
- 感染负荷高于安全线时，组织活性持续下降。
- 成功供氧提高氧供和组织活性。
- 清除感染灶降低感染负荷。
- 组织活性降至 0 时病例失败。

所有指标每次更新后必须限制在 `0–100`。

### 6.3 关卡配置

```js
caseConfig: {
  version: 1,
  primaryCell: 'rbc',
  allyMode: 'wbc_support',
  vitals: {
    oxygen: {
      initial: 55,
      target: 80,
      decayPerSecond: 0.4
    },
    infection: {
      initial: 65,
      target: 20,
      growthPerSecond: 0.3
    },
    tissue: {
      initial: 60,
      target: 75
    }
  },
  goals: {
    oxygenDeliveries: 3,
    infectionSites: 2
  },
  stabilizeSeconds: 5,
  briefing: {
    title: '组织缺氧',
    summary: '感染正在影响受伤组织的氧气供应。',
    outcome: '组织氧供恢复，感染扩散受到控制。'
  }
}
```

### 6.4 地图标记

病例模式新增三个地图标记：

- `L`：肺泡供氧点。
- `T`：目标组织。
- `i`：感染灶。

加载地图时为标记生成稳定节点 ID：

- `oxygen_source_0`
- `tissue_0`
- `infection_0`

AI 只能引用当前地图中真实存在的节点 ID。

### 6.5 通关与失败

病例通关需要同时满足：

- `oxygen >= oxygen.target`
- `infection <= infection.target`
- `tissue >= tissue.target`
- 当前阶段目标全部完成
- 上述状态连续保持 `stabilizeSeconds`

任意条件再次不满足时，稳定倒计时立即重置并显示原因。

病例失败条件：

- `tissue <= 0`

玩家死亡不会直接导致病例失败。玩家从最近存档点复活，并对患者状态施加配置化惩罚。

## 7. AI 病情导演

### 7.1 AI 在评分中的作用

运行时 AI 与 CodeBuddy 开发过程属于两个不同评分项：

- “AI 方向”要求 AI 参与游戏核心玩法。
- “AI 使用情况”要求展示 CodeBuddy 在需求、架构、逻辑和调试中的完整协作证据。

本设计中的 AI 是患者病情导演，而不是聊天窗口或文本润色器。

### 7.2 职责边界

```text
AI：决定下一阶段发生什么病例危机
病例引擎：校验并执行病例危机
玩家：观察指标并作出应对
```

没有 AI 时，本地导演仍可从同一事件库中生成有效危机，保证可玩性；正常联网演示中，AI 根据玩家表现选择事件、位置和严重程度。

### 7.3 首版事件白名单

仅实现四种事件：

| 事件 ID | 作用 | 主要应对 |
|---|---|---|
| `ACUTE_HYPOXIA` | 加快氧供下降，激活指定缺氧组织 | 红细胞紧急供氧 |
| `INFECTION_REBOUND` | 激活休眠感染灶并提高感染增长 | 白细胞清除感染 |
| `TRANSPORT_BLOCKAGE` | 降低自动或玩家运输效率 | 白细胞清除阻塞 |
| `ATP_CRISIS` | 暂时提高技能消耗或减少补给 | 通过供氧恢复代谢 |

单人模式只向 AI 提供当前主控细胞能够处理、或自动友军能够协助处理的事件。双人模式允许使用全部事件。

### 7.4 AI 输入

```json
{
  "schemaVersion": 1,
  "levelId": 3,
  "mode": "single",
  "primaryCell": "rbc",
  "phase": 2,
  "vitals": {
    "oxygen": 52,
    "infection": 34,
    "tissue": 68
  },
  "performance": {
    "deaths": 1,
    "oxygenDeliveries": 2,
    "infectionSitesCleared": 1,
    "atpEfficiency": 0.72,
    "phaseTimeSeconds": 41
  },
  "allowedEvents": [
    "ACUTE_HYPOXIA",
    "ATP_CRISIS"
  ],
  "validTargetNodes": [
    "tissue_0",
    "tissue_1"
  ]
}
```

### 7.5 AI 输出

```json
{
  "eventId": "ACUTE_HYPOXIA",
  "targetNode": "tissue_1",
  "severity": 2,
  "goal": {
    "oxygenDeliveries": 2,
    "timeLimitSeconds": 45
  },
  "doctorLine": "右侧组织出现急性缺氧，请立即恢复氧气运输。",
  "reason": "上一阶段感染控制良好，但供氧恢复速度偏慢。"
}
```

### 7.6 输出校验

服务端和客户端都必须校验：

- `eventId` 必须来自本次请求的 `allowedEvents`。
- `targetNode` 必须来自当前地图的 `validTargetNodes`。
- `severity` 只能是 `1–3`。
- `timeLimitSeconds` 限制在 `30–60`。
- 目标计数限制在 `1–3`。
- 医生台词和原因限制长度并按纯文本展示。
- 不接受 HTML、JavaScript、地图字符串或额外属性。
- 非法输出整体丢弃，不尝试执行部分字段。

### 7.7 调用与回退

- 浏览器只调用 `/api/director`。
- API Key 只能来自服务器环境变量。
- 现有地图生成和树突状细胞 NPC 的浏览器直连 AI 请求也必须迁移服务端或停用。
- 不再把 AI Key 存入 `localStorage`。
- 单次请求超时后立即使用本地导演。
- 每关最多调用两次：开始阶段和第一阶段完成后。
- 本地导演使用与 AI 相同的输出结构和校验器。
- 本地导演使用确定性种子，便于断网演示和自动化测试。

## 8. 编辑器

### 8.1 病例设置面板

新增“病例设置”面板，包含：

- 病例模式开关。
- 单人主控细胞：红细胞/白细胞。
- 单人自动友军模式。
- 三项患者指标初始值。
- 三项通关目标。
- 氧气交付次数。
- 感染灶清除数量。
- 稳定时间。
- 病例标题、开始说明和结束结果。

### 8.2 瓦片面板

病例模式显示：

- 肺泡供氧点 `L`
- 目标组织 `T`
- 感染灶 `i`
- 出生点、存档点、地形、敌人、ATP和知识卡

病例模式隐藏但不删除：

- 金币
- 问号方块
- 管道
- 终点门
- 血小板相关选项

### 8.3 保存校验

病例地图保存前必须验证：

- 主控细胞只能是 `rbc` 或 `wbc`。
- 所有指标与目标在 `0–100`。
- 稳定时间在 `3–10` 秒。
- 需要供氧时至少有一个 `L` 和一个 `T`。
- 需要清除感染时，感染灶数量不少于目标数量。
- 地图只有一个有效出生点。

校验失败时说明具体问题，不保存不可通关的病例配置。

### 8.4 兼容性

- 六个内置关卡全部添加 `caseConfig`。
- 新建地图默认使用病例模式。
- 旧自定义地图没有 `caseConfig` 时继续使用旧通关规则。
- 旧分享码继续导入。
- 病例地图导出和导入时必须保留完整 `caseConfig`。

## 9. 六关故事与主控分配

六关讲述同一名患者从擦伤感染到恢复的完整病例：

| 关卡 | 单人主控 | 故事与目标 |
|---|---|---|
| 血液循环 | 红细胞 | 向受伤组织供氧，并发现异常感染 |
| 白细胞觉醒 | 白细胞 | 清除伤口入口的感染灶 |
| 肺泡迷宫 | 红细胞 | 恢复肺泡氧气交换和运输 |
| 血管奔流 | 红细胞 | 在炎症和阻塞下维持组织供氧 |
| 淋巴结 | 白细胞 | 清理病原并形成免疫记忆 |
| Boss 感染 | 白细胞 | 压制全身感染，保护红细胞运输 |

双人模式中每关都由一红一白共同完成，不受单人主控配置限制。

最终主题：

> 人体健康不是某一个细胞的胜利，而是氧气运输、防御和免疫记忆共同协作的结果。

## 10. UI 与反馈

### 10.1 HUD

- 左上：P1 头像、生命和 ATP。
- 双人时右上：P2 头像和生命。
- 顶部中央：氧供、感染负荷和组织活性。
- 右侧：当前 AI 病例事件、目标进度和阶段。
- 指标达标后显示稳定倒计时。
- 指标恶化时显示倒计时中断原因。

### 10.2 AI 可见性

必须让评委直接看到：

- “AI 病情导演正在分析患者状态”。
- “AI 触发：急性缺氧”。
- 事件目标位置和严重程度。
- AI 选择该事件的原因。
- “AI 导演阶段：1/2”。

AI 事件产生时使用病例提示卡、目标点高亮、HUD 变化和患者指标变化共同反馈，不能只显示文字。

### 10.3 结算报告

结算页展示：

- 患者三项指标变化。
- 红细胞供氧次数。
- 白细胞感染控制数量。
- ATP 使用效率。
- 死亡次数。
- 单人自动友军或双人协作贡献。
- 两次 AI 病情决策、选择原因和玩家应对结果。
- 本关知识结论和下一关病情变化。

## 11. 评分

病例评分不再以金币为核心：

- 患者最终稳定程度：50%。
- 病例阶段目标完成度：30%。
- ATP 使用效率：20%。
- 死亡施加协作评分扣分。

金币、问号方块、管道和终点门不出现在重构后的六张病例地图中。

## 12. 错误处理

- 病例配置非法：阻止编辑器保存；运行时显示明确错误并返回关卡选择，不进入不可通关状态。
- 病例节点缺失：AI 请求前移除依赖该节点的事件。
- AI 无 Key、超时、网络失败或非法 JSON：使用本地导演。
- AI 返回未知字段：拒绝整个响应。
- 自动友军脚本异常：病例引擎使用保底速率继续推进，避免单人地图锁死。
- 双人玩家距离过远：柔性边界限制领先玩家，不传送、不分屏。
- 单个玩家死亡：存档点复活并扣除患者状态；组织活性归零才失败。
- 旧地图：无 `caseConfig` 时进入明确标记的“经典模式”。

## 13. 测试与验收

### 13.1 自动化测试

至少覆盖：

1. 红细胞装载和交付氧气后，病例指标正确变化。
2. 白细胞清除感染灶后，感染负荷正确下降。
3. 指标未全部达标时不能通关。
4. 稳定倒计时中指标恶化会重置。
5. 到达旧终点门不会完成病例。
6. 组织活性归零会触发病例失败。
7. 双人模式强制一红一白。
8. 单人自动友军在双人模式下停用。
9. 旧自定义地图继续使用旧规则。
10. 编辑器病例配置导出、导入、更新后数据不丢失。
11. AI 事件 ID、目标节点和严重度白名单校验。
12. AI 无 Key、超时和非法 JSON 均使用本地回退。
13. 断网本地导演使用固定种子时结果可重复。
14. AI 事件会真实改变病例目标和患者指标。

### 13.2 人工验收

- 六关分别完成一次单人通关。
- 至少完成一次双人完整病例。
- 断网状态完成一关并看到本地导演说明。
- 联网状态展示 AI 根据上一阶段表现生成第二阶段危机。
- 从编辑器创建一张病例地图并成功通关。
- 新玩家只阅读一次教程即可理解当前角色职责。
- 演示过程中不出现金币、问号砖块、管道刷怪或终点通关。

## 14. 三天实施边界

### 第一天：核心闭环

- `CaseEngine`
- 三项患者指标
- 红细胞供氧点和目标组织
- 白细胞感染灶
- 病例通关与失败
- 固定单人角色

### 第二天：编辑器与双人

- 病例设置面板
- 三种病例标记
- 六关配置迁移
- 单人自动协作
- 双人一红一白与共享病例

### 第三天：AI与演示质量

- 服务端 AI 导演代理
- 四种白名单危机
- 本地导演回退
- 病例卡、AI 提示和结算报告
- 自动化测试
- 六关人工通关、数值调整和演示脚本

如果时间不足，缩减顺序为：

1. 保留 CaseEngine、供氧、感染、固定角色和病例通关。
2. 保留本地导演和 AI 服务端代理。
3. 保留六关配置。
