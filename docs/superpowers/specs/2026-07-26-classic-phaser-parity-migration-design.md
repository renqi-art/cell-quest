# 《细胞远征》经典模式 Phaser 等价迁移设计

状态：待书面复核  
日期：2026-07-26  
上位设计：`docs/superpowers/specs/2026-07-26-vue-phaser-typescript-migration-design.md`

## 1. 目的

本设计是已批准的 Vue 3 + Vite + TypeScript + Phaser 迁移方案的经典模式实施增补。目标是把当前仍由 `LegacyGameEngineAdapter` 驱动的经典模式完整迁移到 Phaser，并在行为等价、兼容性和全量验收通过后移除旧 Canvas 运行时。

本轮迁移覆盖：

- 六个经典内置关卡和旧自定义关卡。
- 玩家移动、跳跃、二段跳、蹲下、奔跑、冲刺、受伤、死亡、检查点和重生。
- 尖刺、弹簧、普通地面、特殊地形、碎裂平台、浮动平台和临时平台。
- 普通敌人、大型敌人、分裂敌人、冲刺敌人、Boss 和 NPC。
- 道具、问号方块、补体子弹、敌方攻击和伤害结算。
- 管道刷怪、潮汐、失血区、终点条件和关卡统计。
- 单人、双人、角色职责、动态相机、震动、完整音频、粒子和动画。
- 暂停、恢复、重试、退出、Scene 销毁和重复进入。

病例模式现有的 `CaseDraft`、病例指标和 AI 导演能力保持不变。经典模式和病例模式共享 `GameEngine` 边界及 Phaser 基础设施，但不把两种玩法强行合并成一个领域模型。

## 2. 已确认的现状

当前 `PhaserGameEngineAdapter` 只实现病例模式的基础场景：

- `loadLevel()` 不能独立加载经典关卡。
- 只有基础地形、圆形玩家、左右移动和跳跃。
- 没有经典敌人、危险机关、子弹、冲刺、动态相机和完整音频。
- `GameApp.vue` 对病例使用 Phaser，对经典模式回退到 `LegacyGameEngineAdapter`。

旧经典运行时的主要依赖链为：

```text
js/levels/*.js
→ js/game.js 中的 Level 解析和逐帧循环
→ js/entities.js 中的 Player / Enemy / Boss / Item / Projectile
→ js/config.js 中的 Game 全局状态、常量、Sfx 和存档数据
→ Canvas 绘制、相机与 DOM HUD
```

旧地图字符至少包含：

| 字符 | 语义 |
|---|---|
| `#`, `=`, `S`, `B`, `p` | 固体或特殊地形 |
| `^`, `V` | 危险机关 |
| `J` | 弹簧 |
| `_` | 碎裂平台 |
| `P` | 玩家出生点 |
| `g`, `G`, `t` | 普通、大型或冲刺类敌人 |
| `b` | Boss |
| `N` | NPC |
| `C` | 检查点 |
| `F` | 终点 |
| `?`, `X` | 问号方块 |
| `D`, `O`, `M`, `o`, `f`, `d`, `n`, `a`, `*` | 各类道具 |

关卡还带有字符图之外的 `floatPlatforms`、`pipeSpawners`、`tutorials`、`knowledgeCards`、`miniSpawnArea` 等配置。迁移不能只解析字符图而遗漏这些附加结构。

## 3. 方案选择

### 3.1 采用方案：类型化领域机制 + Phaser 表现适配

将可确定、可测试的规则写成不依赖 Phaser 的 TypeScript 模块；由 Phaser Scene 负责对象生命周期、碰撞接线、输入、相机、音频、动画和渲染。

优点：

- 关键规则可以用 Vitest 固定时间步测试，不依赖真实浏览器。
- Phaser 升级或替换时，关卡格式、伤害规则和计时状态机无需重写。
- 避免把旧 `game.js` 逐行复制到一个新的巨型 Scene。
- 病例和经典玩法可以共享引擎边界，但保持各自清晰的领域模型。

### 3.2 未采用方案：逐行翻译旧 Canvas 代码

虽然初期速度快，但会保留 `Game` 全局状态、隐式依赖和帧率耦合，无法达到 TypeScript ES Modules 化和解耦目标。

### 3.3 未采用方案：完全依赖 Phaser Arcade 默认行为

默认物理适合快速原型，但旧游戏包含土狼时间、跳跃缓冲、可变跳高、冲刺锁速、特殊地形和双人相机。若完全依赖默认响应，关键手感难以等价。迁移采用 Arcade Body 承载碰撞，同时用显式控制器维护行为参数和状态。

## 5. 数据边界与兼容

### 5.1 经典关卡定义

经典关卡进入 Phaser 前必须转换为已校验的 `ClassicLevelDefinition`。该定义保留现有字符地图和附加配置，不允许 Scene 直接读取 `window` 上的旧关卡对象。

核心数据包括：

- 稳定 `id`、名称、尺寸、天空或背景配置。
- 原始字符行，行宽按既有规则补空格。
- 教程、知识卡、浮动平台、管道刷怪和小型敌人生成区。
- 难度与关卡特有机制标志。

解析结果为 `ParsedClassicLevel`：

- 瓦片层和特殊地形。
- 玩家、敌人、Boss、NPC、道具、检查点和终点生成描述。
- 浮动、碎裂、临时平台及刷怪描述。
- 不包含 Phaser 对象。

### 5.2 旧数据导入

六个内置关卡数据迁移为 TypeScript ES Modules，值保持不变。旧自定义关卡和 `CQ!` 分享码仍通过兼容解析器进入同一 `ClassicLevelDefinition`。

兼容规则：

- 已知字符语义不变。
- 未知字符按空格降级并产生可观察警告，不执行任意代码。
- 缺失可选数组使用空数组。
- 非法尺寸、无出生点、无终点或越界附加对象返回结构化校验错误。
- 旧关卡不能依赖 `eval`、动态脚本标签或全局构造函数。

### 5.3 运行时事实来源

Scene 和其运行时对象是逐帧状态唯一事实来源。Pinia 只接收低频 HUD、暂停、死亡、通关和统计快照，不镜像每个实体坐标。

## 6. 固定时间步与手感等价

经典逻辑使用 60 Hz 固定模拟步长。Phaser `update` 的实际 `delta` 通过累加器转换为固定 tick，并限制单帧最大追赶次数，避免切回标签页后一次执行大量物理步。

玩家控制器显式维护：

- 水平加速度、地面和空中摩擦、最大速度。
- 土狼时间、跳跃缓冲、二段跳和松键截断。
- 站立/蹲下碰撞体切换及头顶空间检查。
- 奔跑触发、能量消耗和停止条件。
- 冲刺持续时间、冷却、方向锁定、水平碰撞和期间受力规则。
- 受伤无敌、击退、护盾、恢复、死亡和检查点重生。

行为基线使用旧运行时测得的速度、距离、帧数和状态变化，不以“看起来差不多”作为验收。对帧率敏感的常量转换为秒或固定 tick 常量，并保留来源说明。

## 7. 地形、机关与平台

`TileRegistry` 为每个字符声明渲染种类、碰撞种类和机制标签。解析器不包含具体碰撞代码。

地形系统覆盖：

- 全碰撞固体。
- 单向或特殊平台。
- 尖刺及方向性危险。
- 弹簧触发速度、冷却和音效。
- 失血区、潮汐影响区和其它减速/消耗地形。
- 碎裂平台的 `solid → shaking → gone → solid` 状态机。
- 正弦浮动平台和玩家随平台位移。
- 血小板临时平台的生成、碰撞和生命周期。

危险触发统一产生 `DamageEvent`，避免尖刺、敌人和 Boss 分别直接修改玩家的多个字段。

## 8. 敌人、Boss、NPC 与刷怪

普通敌人共享基础 Actor 和战斗状态，不使用一个包含所有类型分支的超大类。

拆分如下：

- 葡萄球菌：巡逻、边缘转向、接触伤害。
- 大型葡萄球菌：独立生命值、死亡分裂和奖励。
- 链球菌：待机、预警、冲刺、撞墙和冷却状态。
- 小型敌人：生成区或分裂生成、简化属性。
- Boss：阶段、技能冷却、受击、护盾、召唤、异常状态和死亡出口条件。
- NPC：独立交互范围和一次性/可重复交互状态。
- 管道刷怪：计时、触发条件、最大生成量和冷却。

敌人决策在固定 tick 执行，视觉动画可以按实际帧插值。随机掉落和自适应难度使用可注入随机源，测试使用固定 seed。

## 9. 战斗、子弹、道具与问号方块

`CombatSystem` 是伤害、无敌、击退、击杀和奖励结算的单一入口。

必须覆盖：

- 玩家接触伤害、踩踏、冲刺、近战和主动技能。
- 补体子弹的生成、飞行寿命、地形碰撞、敌人命中和回收。
- Boss 和敌方范围攻击。
- 问号方块顶撞、使用状态和道具生成。
- 护盾、氧气、补体、硬币、食物、饮料、营养、ATP、记忆、经验和装备类道具。
- 掉落、背包容量、统计和音效事件。

频繁创建的子弹、粒子和伤害数字使用 Phaser Group 或对象池；Scene 销毁时全部释放。

## 10. 双人和动态相机

双人输入保持现有按键映射和角色职责。每名玩家拥有独立输入状态、碰撞体、生命与技能状态；共享关卡、相机和全局目标。

`CameraDirector` 支持：

- 单人平滑跟随和世界边界。
- 双人包围盒中心跟随。
- 根据两人距离在限定范围内平滑缩放。
- 防止玩家长期离开可视范围的约束或提示。
- 受伤、冲刺、Boss 阶段和机关触发的分级震动。
- 暂停时停止跟随，恢复时不跳变。
- 重生和 Scene 重建时立即校正。

相机只读取玩家与世界状态，不修改玩家物理状态。

## 11. 音频、动画与资源

`ClassicAudioController` 封装 Phaser Sound，不允许 Actor 直接访问全局 `Sfx`。

音频事件至少覆盖：

- 跳跃、二段跳、蹲起、冲刺和角色切换。
- 受伤、死亡、踩踏、近战、射击和命中。
- 道具、硬币、记忆、检查点和通关。
- 弹簧、碎裂平台、管道刷怪和潮汐。
- Boss 预警、阶段切换和技能。
- 关卡背景音乐、暂停、恢复、切关和销毁。

若现有声音为 Web Audio 合成而非文件资源，则把波形和节奏参数迁移为类型化音效定义，由音频控制器创建；不继续保留全局 `AudioContext`。浏览器自动播放限制通过首次用户交互解锁，失败时游戏继续运行并向 UI 发出非致命音频状态。

动画和粒子响应领域事件，不参与命中判定。`reduced-motion` 只削弱视觉震动和粒子，不改变物理与伤害结果。

## 12. GameEngine 与生命周期

`GameEngine` 公共边界继续保持 Vue 与 Phaser 解耦。`loadLevel(levelId, options)` 在 Phaser 适配器内加载经典关卡；`loadCaseDraft` 加载病例模式。

适配器职责：

- 根据载荷创建 `ClassicScene` 或 `CaseScene`。
- 把暂停、恢复、重试、退出和输入命令路由到活动 Scene。
- 将 Scene 的 HUD、死亡、完成和错误转换为 `GameEngineEventMap`。
- 保证同一时刻只有一个活动游戏 Scene。

销毁要求：

- 移除键盘、指针和窗口监听。
- 停止并销毁音频。
- 清理计时器、tween、collider、overlap 和事件订阅。
- 销毁 Group、对象池和 Scene 局部服务。
- 重复进入/退出不会增加监听器数量或并行循环。

## 13. 错误处理

错误按边界分类：

- `ClassicLevelValidationError`：关卡内容不合法，阻止进入并向 Vue 提供可读原因。
- `ClassicAssetError`：非关键视觉或音频资源失败时降级；关键地图资源失败时阻止启动。
- `ClassicRuntimeError`：Scene 创建或固定 tick 出现不可恢复错误时停止 Scene，记录上下文并返回主界面。
- `ClassicCompatibilityWarning`：未知但可安全忽略的数据，允许进入并记录警告。

不得静默回退到 Legacy 运行时。正式切换前若 Phaser 经典模式失败，应显示错误并保留旧提交作为 Git 回退点；运行时双轨回退会掩盖问题并延长遗留依赖。

## 14. 实施批次与阶段门

### 批次 A：关卡与测试基线

- 固定六关、旧自定义关卡和分享码样本。
- 建立类型、字符注册表、解析器、校验器和 TypeScript 关卡模块。
- 记录玩家、机关、敌人、相机和音频行为基线。

阶段门：旧数据全部可解析；未知字符和非法结构测试通过；没有运行时脚本执行。

### 批次 B：玩家与基础地形

- Classic Scene 骨架、固定时间步、输入、玩家控制器。
- 固体、蹲下、跳跃、二段跳、尖刺、弹簧、检查点、死亡和重生。
- 单人相机和基础音效。

阶段门：技术验证垂直切片的全部指标通过。

### 批次 C：敌人、战斗、子弹与道具

- 普通、大型、分裂和冲刺敌人。
- 近战、踩踏、冲刺伤害、补体子弹、问号方块和完整道具。
- 击杀、奖励和统计。

阶段门：代表关卡可在 Phaser 中从出生点完成到终点，战斗事件与基线一致。

### 批次 D：特殊世界机制

- 碎裂、浮动和临时平台。
- 潮汐、失血区、管道刷怪、小型敌人生成区。
- NPC、Boss 和其阶段技能。

阶段门：六关所有机制均有自动化覆盖，六关均可完成。

### 批次 E：双人、动态相机和完整表现

- 双人输入、角色职责和协作流程。
- 双人包围盒相机、缩放、边界和完整震动。
- 背景音乐、全部音效、动画、粒子和无障碍降级。

阶段门：单人和双人核心流程、暂停、死亡、重试、退出和重进通过。

### 批次 F：正式切换与遗留删除

- `GameApp.vue` 对经典和病例都只创建 `PhaserGameEngineAdapter`。
- 编辑器试玩使用相同 Phaser 经典加载器。
- 删除 `LegacyGameEngineAdapter`、`window.CellQuestLegacy` 消费者和 HTML 旧脚本入口。
- 删除不再被构建、服务或测试引用的旧前端业务脚本。

阶段门：静态搜索、全量测试、生产构建、离线包和人工 QA 全部通过后才能宣告迁移完成。

## 15. 测试策略

所有行为按 TDD 顺序实施：先写失败测试，确认失败原因正确，再写最小实现并重构。

### 15.1 单元测试

- 每个地图字符和附加配置的解析。
- 玩家固定 tick 移动、跳跃、蹲下、冲刺和受伤状态。
- 尖刺、弹簧、碎裂平台、潮汐和刷怪状态机。
- 每类敌人状态转换、伤害、死亡、分裂和掉落。
- 子弹寿命、地形碰撞、敌人命中和池回收。
- 检查点、终点、统计和自适应难度。
- 相机目标中心、缩放限制和震动衰减。
- 音频事件到音效定义的映射。

### 15.2 Phaser 集成测试

- 真实 Arcade Body 的地形和实体碰撞。
- Scene 创建、暂停、恢复、重启和销毁。
- 单人和双人输入路由。
- 玩家、敌人、Boss、子弹和道具碰撞组。
- 相机边界、双人缩放和震动。
- GameEngine 事件和 HUD 快照。

### 15.3 端到端测试

- 六关分别进入、关键机制触发、到达终点和结算。
- 单人、双人、角色交换、死亡重试和检查点。
- 自定义关卡及 `CQ!` 分享码导入后用 Phaser 运行。
- 暂停、退出、重进和连续切关。
- 编辑器创建、试玩、返回、修改和再次试玩。
- 生产预览与离线包无资源 404、控制台错误或未捕获异常。

### 15.4 人工等价验收

每关记录：

- 关键路线可达性。
- 手感、碰撞和机关响应。
- 敌人/Boss 行为。
- 相机跟随和双人可见性。
- 音效与背景音乐。
- 死亡、检查点、重试、通关和统计。

人工结论必须绑定候选 SHA，不得用开发过程中的旧截图代替。

## 16. 性能预算

- 固定模拟保持 60 Hz，标签页恢复后不出现长时间追赶。
- 常规场景目标 60 FPS；验收设备持续低于 50 FPS 视为需要分析。
- 子弹、粒子和伤害数字使用池化，活动数量设上限。
- Vue 不接收逐帧坐标。
- 相机、碰撞和敌人查询使用 Phaser Group、空间索引或可见范围，避免每帧全量两两比较。
- 连续进入和退出十次后，监听器、Scene、音频节点和活动定时器数量不增长。

## 17. 安全与可访问性

- 旧关卡和分享码只能产生白名单数据，不能执行代码或注入 HTML。
- 用户文案继续按纯文本渲染。
- 键盘控制、暂停和退出保持可达。
- 音量设置、静音和浏览器音频解锁失败不会阻止游戏。
- `prefers-reduced-motion` 降低相机震动和非必要粒子强度。

## 18. 回退策略

- 每个批次形成独立、可运行、可测试的提交。
- 批次 F 前保留旧运行时文件，但不得继续向旧运行时添加功能。
- 每个阶段门失败时只回退当前批次，不破坏已通过的关卡数据和领域模块。
- 批次 F 删除遗留入口前记录明确 Git 基线；若发布验收失败，回退候选提交，而不是在同一版本中动态选择 Legacy。

## 19. 最终验收标准

只有以下条件全部满足，经典 Phaser 迁移才算完成：

1. 六个内置经典关卡都由 Phaser 加载、运行和完成。
2. 旧自定义关卡及 `CQ!` 分享码可以导入并运行。
3. 玩家移动、跳跃、二段跳、蹲下、奔跑和冲刺达到记录的行为基线。
4. 敌人、大型敌人、分裂、冲刺、Boss 和 NPC 行为可用。
5. 尖刺、弹簧、碎裂、浮动、临时平台、特殊地形、潮汐和管道刷怪可用。
6. 道具、问号方块、补体子弹、敌方攻击、伤害、掉落和统计可用。
7. 检查点、死亡、重生、终点和关卡结算正确。
8. 单人和双人核心流程通过，角色职责和交换保持。
9. 单人跟随、双人动态缩放、边界和震动正确。
10. 背景音乐和所有关键事件音效在支持音频的浏览器中正确播放。
11. 暂停、恢复、重试、退出、重进和 Scene 销毁无泄漏。
12. Vue 与 Phaser 只通过 `GameEngine` 和事件/快照通信。
13. `GameApp.vue`、编辑器试玩和生产入口不再创建 `LegacyGameEngineAdapter`。
14. `window.CellQuestLegacy`、旧脚本顺序加载和旧 `game.js` 运行时入口已移除。
15. TypeScript、ESLint、单元、组件、服务、Playwright、内容验证、证据验证和生产构建全部通过。
16. 最终发布验收报告绑定当前候选 SHA，并重新完成六关单人、代表性双人和自定义关卡人工 QA。

任何一项缺失都必须继续标记为 `RELEASE BLOCKED`，不得用“已有替代实现”“病例模式可运行”或“局部 Phaser 垂直切片”代替经典模式完整等价迁移。
